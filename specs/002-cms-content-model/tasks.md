## Path Conventions and Shared Constraints

- One existing application: native definitions in `seed/seed.json`; preserve `astro.config.mjs`, `src/live.config.ts` and the canonical foundation. Test support stays in `tests/browser/`; future review evidence stays in `specs/002-cms-content-model/evidence/`.
- Reuse pinned Node 24.21.0/npm 12.2.0, Astro 7.3.5, EmDash 1.1.0, PostgreSQL 18.6 and Playwright 1.63.0. No dependency change, second development runtime, migration framework, custom CMS/Admin/RBAC/Media/Search, publication hook or reference adapter.
- Every collection task includes the accepted native `drafts`, `revisions`, `preview`, `scheduling`, title/date configuration, Thai semantic labels and logical field ordering. Search/SEO remain native and are enabled only where useful. No duplicate system ID/slug/author/time/status fields or new permissions.
- **Verbatim Data Model constraints**: “**S** is native schema save-time requiredness; **O** is optional at save and Publish/Schedule except native built-in constraints and supplied-value checks.” Configure S fields with native “`required: true`”; “all other content/reference fields remain non-required, with their native supplied-value constraints.” No additional completeness, length, uniqueness, required taxonomy, meaningful-body/gallery/channel or conditional-reference rule is inferred. Valid zero/false/native boolean 0/1 remain valid values.
- Quoted field/type/enum/cardinality constraints in tasks below are from the approved Data Model. Domain dates use native offset-aware datetime; domain expiry, closure, review dates and operational status do not auto-unpublish. Optional omissions may persist through direct native Publish/Schedule; staff editorial responsibility is not an article approval or confirmation workflow.
- Seed is bootstrap intent, not proof of an initialized DB's schema. At each story verification join, inspect/apply only its approved native definitions through supported EmDash schema operations on the authorized development instance; verify matching existing definitions rather than destructively reseeding. Native relation declarations precede field bindings; bind each exact source field to the named relation/side in the Data Model so automatic field-created names do not produce duplicate edges. No direct internal-table writes or migration subsystem.
- Prepare synthetic public-publishable fixtures through native APIs; do not overwrite real records, invent official inventories, or put editorial population into the bootstrap seed. Taxonomy attachments are added as their collections are introduced; never bind a field to an undefined target.
- Tests use the existing README development-only `POST /_emdash/api/setup/dev-bypass?token=1` and distinct native role credentials. Tokens stay in memory or ignored mode-0600 scratch, never logs/evidence. Native account/role operations provide Contributor, Author/Editor and Administrator fixtures; an Admin token alone cannot prove draft-only restrictions. No production Passkey automation or custom impersonation.
- Use returned IDs and current `_rev`/supported concurrency preconditions. Re-read uncertain outcomes before a retry. Run runtime/schema/scheduler checks serially, and clean only owned synthetic fixtures, temporary consumers, credential scratch, foreground services and containers started by the run. Never delete persistent volumes or real media/data.
- Future implementation requires the existing workflow's approvals, actual readiness and bounded Product Owner authorization. Multica agents execute the authorized tasks; ChatGPT performs Independent Review of their artifacts/evidence; the Product Owner provides final acceptance. Author and Independent Reviewer remain separate. This task list neither grants authorization nor creates another approval workflow.
